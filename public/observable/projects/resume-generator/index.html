Résumé Generator

Check it out here: Resume Generator

Introduction

This project turns a familiar, high-friction workflow into a focused AI product: take a job description, analyze the role, generate resume content from a grounded work-history corpus, and render the result as a polished PDF. The goal is not to spam generic resumes, but to produce a document that reflects the candidate's actual background while speaking clearly to the role.

For the portfolio, the value of the project is the product surface as much as the generated document. It includes a public Svelte interface, text and file input modes, session verification, asynchronous job handling, PDF delivery, and a writeup that explains the system tradeoffs.

Initial development

The first version established the core data flow: combine a structured longform history with the job description, ask the model for tailored content, and convert the result into a professional PDF. Plain markdown was not enough because the output needed stable layout, predictable spacing, and a format recruiters and applicant systems can open without ceremony.

The rendering layer therefore converged on a Chromium-based PDF pipeline with custom CSS and a constrained markdown/HTML format. That constraint is important: the model gets enough structure to express sections and bullets, while the renderer keeps ownership of typography, margins, and document polish.

Operationalization

Putting the tool on the site required the surrounding production work: a Svelte frontend, Cloudflare Turnstile verification, API Gateway routing, job submission and polling, file handling, storage metadata, a serverless worker that calls the model API, and a PDF rendering environment with Chromium available.

The LLM request is built from versioned candidate history, role inputs, and formatting instructions. The public interface accepts pasted text or uploaded job-description files, then moves through explicit loading, success, and error states so the user understands what the system is doing.

Issues and Opportunities

The main product challenge was avoiding keyword soup. A model can over-optimize toward job-posting terminology and produce a resume that looks aligned but reads hollow. The better pattern is a staged flow: first analyze the job description for role priorities, then generate resume content that maps real experience to those priorities in plain language.

The next improvements are evaluation-oriented: compare outputs across prompts, record the reasoning behind section selection, and add reviewer controls for tone and seniority. Those additions would make the tool more useful while preserving the important boundary that the resume should remain grounded in real experience.
