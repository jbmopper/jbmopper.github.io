Miscellaneous Grounding

This project combines the portfolio site development, resume generation Lambda, and RAG chatbot work into one applied AI infrastructure story. The common thread is grounding: generated behavior is tied back to durable source documents, known routes, gated API calls, and observable production workflows.

It is less a single feature than a small system of surfaces around juliusm.com: the Astro/Svelte shell, this Observable writeup corpus, the resume-generation backend, and the chatbot that answers from the same project materials.

Scope

  • an Astro and Svelte portfolio shell that hosts the public site and resume widget
  • an Observable writeup repo exported into the main site as technical project pages
  • an AWS-backed resume generation flow with challenge verification, async jobs, and PDF delivery
  • a Vertex AI RAG chatbot grounded in the portfolio and project corpus

Site Development

The site is split across a static portfolio shell and this Observable Framework workspace. Keeping the exploratory writeups here makes it easier to iterate on large data files, notebooks, and visualization components without dragging the main site repo through every experiment.

The export bridge copies built Observable pages, shared theme tokens, and the shared project catalog into the Astro site. That gives the public site a cleaner deployment shape while preserving rich interactive writeups for deeper technical material.

AI-assisted development was useful here because the work was mostly integration-heavy: route conventions, export scripts, visual checks, auth edges, and deployment plumbing. The productive pattern was not vague prompting, but a requirements, implementation, review, and verification loop with enough context loaded for the assistant to stay inside the system's constraints.

Resume Lambda

The resume generator turns a submitted job description into a tailored PDF resume. The backend builds a model request from versioned candidate material, prompt templates, and the job description, then asks the model for a structured Markdown/HTML response that can be rendered through Chromium with custom CSS.

Operationalizing that local workflow required the surrounding product machinery: Cloudflare Turnstile challenge checks, API Gateway routing, session authorization, async job submission, polling, storage metadata, expiring PDF URLs, and a mock mode so the frontend remains testable without deployed secrets.

The central product lesson was that LLMs happily over-optimize for technical keywords unless the flow gives them a stronger target. The next iteration splits generation into a planning step and a drafting step so the model first chooses a resume strategy, then writes a more human, evidence-oriented document against that strategy.

RAG Chatbot

The chatbot uses the project writeups and supporting site documents as its retrieval corpus. This makes the portfolio self-describing: the same source material that explains the work also grounds answers about the work.

The live integration routes chat through a frontend assistant surface into a server-side API layer backed by Google Cloud Vertex AI and RAG Engine. The default managed vector store is enough for this small corpus, and the system remains relatively simple: ingest the documents, select an embedding model, tune chunking, and let Gemini call retrieval as needed.

The most interesting failure mode was conversation state. Gemini's RAG behavior depends on thinking being enabled and on threading thought signatures through the conversation history. Once that was understood, Langfuse instrumentation made it easier to inspect model behavior, including the RAG query generated behind the scenes.

Grounding Pattern

The combined project is a reminder that AI product work is mostly about context control. The useful pieces are not only prompts or model calls, but the surrounding system that decides what the model can see, how requests are authenticated, where outputs are stored, which routes are canonical, and how failures become visible enough to fix.
