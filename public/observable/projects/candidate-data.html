Technical

The Python orchestrator handles multi-format document extraction (txt, md, rtf, html, docx, odt, pdf), stores artifacts in S3, and calls the Anthropic Claude API for document generation. The Node.js renderer uses Puppeteer with headless Chromium to produce PDFs from structured Markdown.

The AWS Lambda was integrated securely into juliusm.com using Cloudflare Turnstile, AWS WAF and API Gateway with JWT session management, least-privilege IAM, S3 with SSE encryption and TLS-only policy, pre-commit secret scanning with gitleaks

Large Language Models and Deep Learning Fundamentals

Year: 2025-2026 · Status: Writeup available

Narrative

Implemented a Transformer language model (based on Stanford CS336: Language Models from Scratch assignment 1) end-to-end in PyTorch. The assignment provided a basic architecture via testing hooks which validated the performance of from-scratch implementations which subclassed the most-basic-possible PyTorch classes in order to integrate with the auto-differentiation and backpropagation functions. Additionally, an optimizer, learning rate scheduler, training loop, and nucleus-sampling decoder were implemented.

The implementation included an efficient tokenizer with special token handling, embedding and unembedding layers, and transformer layers that included norms, the attention mechanism, rotary positional encoding and feed-forward networks. This built knowledge of PyTorch, transformer and deep learning architectures, efficient encoder implementations, numerical stability, CUDA and MPS deep learning backends, and decoder design.

Subsequently, the architecture was documented in detail and calculations of estimated performance were performed. Benchmarks were conducted across a grid of settings to assess actual performance, which is significantly lower than theoretical. More interestingly, this analysis illustrated the impact of the quadratic asymptotic complexity in sequence length of the attention mechanism and the impact of batch size on avoiding a performance penalty from kernel launches.

Nvidia Nsys profiles were collected across various model settings and scenarios to gain familiarity with the Nsight tooling and observe the impact of, for example, model dimensions that break alignment with the CUDA warp dimensions.

A two-stage hyperparameter sweep was conducted over optimizer parameters. This work included integrating the training class with the wandb sweep API which provided a bayesian search algorithm and early-stopping. A novel metric was created to elicit the desired early stopping behavior. Specifically, that behavior was for the model to initially display increasing loss. The metric created rewarded early increasing loss while preserving the overall prioritization of low evaluation loss, and was successful at eliciting the desired early stopping behavior.

Architectural variations (ablations) were conducted to investigate the impact of various architectural variations. The impact of these on training behavior were analyzed and these changes were found to negatively impact model convergence and best evaluation loss.

The results of this extensive research were compiled and documented as a series of analytic notebooks on the juliusm.com portfolio site.

In order to make the model suitable for demonstration inference on juliusm.com, a KV cache was implemented, again from scratch, and the decoder was rewritten. The model was then exported to a common runtime format to run inference inside a serverless backend instance and integrate with the site.

Technical

The tokenizer was a GPT-2-style byte-pair encoding tokenizer. Standard scaled dot-product attention was used after the RoPE rotary positional encoder step. The architecture featured an RMS pre-norm and SwiGLU FFN. The optimizer was the AdamW optimizer, and a standard cross-entropy loss function was used. The training was monitored by wandb integration, conducted deterministically by controlling random seed values, and standard checkpointing and S3 uploads were performed. The einx package and jaxtyping hints were used to increase readability and ergonomics of the code.

Estimated performance calculations used both fp32 on MPS and mixed-precision on CUDA. Benchmarks were done on an Apple M4 with 10 GPU cores and 24GB unified memory and on CUDA via Docker using Nvidia profiling images. The Torch benchmark Timer class and BlockedAutorange method was used to perform architecture sweeps on MPS and asses accuracy of performance estimations, while more standard timing-based benchmarks were used to compare MPS and CUDA. Models were compiled for CUDA via the Torch inductor compiler and used automatic mixed precision, which was supported by the RTX 4090 (L4) systems used.

Hyperparameter sweeps used the wandb sweep API with bayesian search and hyperband early stopping. Ablations included switching from pre-norm to post-norm, removing the norm altogether, changing the FFN from SwiGLU to SILU, and removing the RoPE functionality.

ONNX was used to export model snapshots for the web-based inference service. While the einx package had been used to write readable, streamlined code, ONNX export required rewriting some sections in vanilla PyTorch (more reshaping and squeezing/unsqueezing). This work was conducted alongside the KV cache implementation.
