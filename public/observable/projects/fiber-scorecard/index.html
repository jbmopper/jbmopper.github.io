Introduction

This project is a simple demonstration of a workflow created in Copilot Studio, Microsoft's low-code platform. The system uses the natural language power of LLMs to compare simulated human notes from different stakeholders and reach conclusions about responsibilities for cost overruns. Your author chose to build the demo around the fiber construction domain, and the "AI SDLC" system was used to help guide domain research and create specifications for generating synthetic data, as well as the overall plan for the demonstration.

In a nutshell, two source systems were simulated: a project management system with the project manager's build notes, and an ERP with change order justifications. The change order justifications are supplied by simulated vendors who, per the setup, don't take responsibility when they cause an overrun, so the messy project manager notes have to be examined. The business problem being solved in this demo is the time-consuming and tedious task of correlating the project manager notes with the change order justification and drawing the conclusion about fault. The benefit of simulated data is that the "true" fault used to generate the text is known and the system's performance can be assessed against that ground truth.

Implementation

The project management system and ERP change order table are represented as two "messified" spreadsheets which are ingested into Microsoft Dataverse tables via generated Power Query routines within Power Apps dataflows. A Copilot Studio workflow was created to pull the project manager notes and vendor change order justifications for the simulated jobs from these tables. The workflow goes job by job, compares the change order justifications with the project manager's notes, and assigns blame. This analysis produces a structured output which is saved to a third Dataverse table.

A Power BI dashboard was created on this output data in order to visualize the results. On invoices alone, the simulated vendor Kestrel Ridge Networks has the lowest overrun in the data (7.3%) and Redfern Underground the highest (16.2%). Once fault is assigned, the two swap: about $951k of overrun is attributed to Kestrel's own fault, the most of any vendor, against about $141k for Redfern.

In addition, a Copilot Studio agent was created with links to the Dataverse tables. This agent provides a conversational interface to drill down into the data.

Measured against the ground truth, the system assigned the correct fault party on 91.1% of items (834 of 915) and the correct cause code on 96.4%. The system is effective at performing the analysis and answering questions about the data, showing how Copilot Studio and the Microsoft platform can be used to efficiently create AI-based workflows that make difficult business problems easily solvable.

Conclusion and Loose Ends

The main loose end is the slowness of the drill-down agent. It was observed to perform repeated queries on the data, indicating it was cross-referencing rows internally. The solution may be to add additional columns to the labels table in order to eliminate this extra processing.

But overall, this demonstration shows that Copilot Studio is an able platform for building accessible tools that can solve complex business workflow problems. The analysis simulated in this demonstration would be very time-consuming if done manually, and the accuracy figures above indicate the system, even after a single iteration, is capable of delivering output good enough to be useful.
